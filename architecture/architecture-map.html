Promum AI: architecture map

Conceptual diagram, snapshot of 4 October 2026: who uses the platform, which modules it consists of, how the orchestrations (chat, search, research) work, where the data lives and how models are connected. Solid frames mean working; dashed frames mean planned.

How the work flows

A question about data (chat)

  1. Permissions: which ERP objects the employee may access.
  2. The fast model writes a calculation plan (up to 4 at once).
  3. The gateway reads the ERP replica; the calculation layer computes every row, adds names and control totals, and builds Excel.
  4. If there is no data or too little, the platform does not build an empty report: the model comes back with a question on how to proceed.
  5. The deliberate model writes the answer from the results; a dashboard on request.
  6. Verification: every number must come from the data; otherwise the model corrects the answer.

Internet search

  1. The employee turns search on; if it is off and an answer is impossible without outside facts, the platform suggests turning it on.
  2. Queries are anonymized first (company data does not leave).
  3. Search and page reading run directly or through the web gateway.
  4. The answer has links [n]; links and numbers are checked against what was read.

Research

  1. The deliberate model writes a plan; the employee edits and launches it.
  2. Queue (the administrator can move a job up or cancel it).
  3. Workers run in parallel: internet (quotes are checked against pages) and ERP (numbers against calculations).
  4. Gaps lead to a second wave; the report has links [n] and [D] marks for company data.
  5. Numbers and links are verified; a short version goes to the chat, the full report is a PDF (A4, charts and tables), a PPTX deck and Excel.
